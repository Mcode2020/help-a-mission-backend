# 03 — API Specification & Response Contracts

**Project:** Help A Mission Welfare Society — Backend API  
**Base URL:** `/api/v1`  
**Data Format:** JSON (`application/json`)  

---

## 1. Global Standard Response Format

All API responses return an authoritative `X-Request-ID` header and follow a uniform JSON structure.

### Success Response (`200 OK`, `201 Created`)
```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "requestId": "req_8f3a9d21-4b10-4c8d-9e12-8238127391ab",
    "timestamp": "2026-10-06T16:00:00.000Z",
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 142,
      "totalPages": 8
    }
  }
}
```

### Error Response (`400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict`, `429 Too Many Requests`, `500 Internal Error`)
```json
{
  "success": false,
  "error": {
    "code": "PERMISSION_DENIED",
    "message": "You do not have the required permission (reports:export) to perform this action.",
    "details": null
  },
  "meta": {
    "requestId": "req_8f3a9d21-4b10-4c8d-9e12-8238127391ab",
    "timestamp": "2026-10-06T16:00:00.000Z"
  }
}
```

---

## 2. Global Headers & Requirements

- `X-Request-ID`: Generated by server if not provided; included in all logs and audit entries.
- `X-Client-Trace-ID`: Optional client correlation identifier.
- `X-Device-ID`: Pseudonymous device UUID generated by frontend.
- `Idempotency-Key`: Mandatory on financial mutation endpoints (`POST /donations/order`).

## 3. Public Routes (`/api/v1/public`)

### 3.1 CMS Homepage Data
`GET /api/v1/public/home`
- **Auth:** None
- **Response:** All published homepage sections (Hero, About, Impact Cards, Initiatives, Gallery, Donation config, Footer, SEO).

### 3.2 Public Gallery
`GET /api/v1/public/gallery?category=camps&page=1&limit=12`
- **Auth:** None
- **Response:** Array of published gallery items linked to public media asset URLs.

### 3.3 Public Initiatives
- `GET /api/v1/public/initiatives` — List published initiatives.
- `GET /api/v1/public/initiatives/:slug` — Detailed view of a single published initiative.

### 3.4 Public Donation Configuration
`GET /api/v1/public/donation-config`
- **Auth:** None
- **Response:** Suggested amounts, custom amount toggle, minimum amount, currency.

## 4. Payment & Webhooks (`/api/v1/donations` & `/api/v1/webhooks`)

### 4.1 Create Razorpay Donation Order
`POST /api/v1/donations/order`
- **Headers:** `Idempotency-Key: <uuid>`
- **Request Body:**
  ```json
  {
    "amountMinor": 100000,
    "currency": "INR",
    "donorName": "Anita Sharma",
    "donorEmail": "anita@example.com",
    "donorPhone": "+919876543210",
    "message": "In support of the health drive"
  }
  ```
- **Response (`201 Created`):**
  ```json
  {
    "success": true,
    "data": {
      "donationId": "d7a9b1c2-...",
      "razorpayOrderId": "order_Nz18293nJ",
      "amountMinor": 100000,
      "currency": "INR",
      "keyId": "rzp_test_..."
    }
  }
  ```

### 4.2 Razorpay Signed Webhook Ingestion
`POST /api/v1/webhooks/razorpay`
- **Auth:** Signature verification via HMAC SHA256 using `RAZORPAY_WEBHOOK_SECRET` and raw request body.
- **Header:** `X-Razorpay-Signature: <signature>`
- **Processing:** Deduplicates `provider_event_id`. Updates donation status to `captured`, upserts donor account in `users`, and queues receipt. Returns `200 OK`.

## 5. Donor Portal Routes (`/api/v1/me`)

Requires valid donor server session cookie (`user_session`).

- `GET /api/v1/me` — Current donor profile details.
- `PATCH /api/v1/me` — Update name/phone profile details.
- `GET /api/v1/me/donations` — List donor's own past donations.
- `GET /api/v1/me/donations/:id` — View specific donation (enforces `WHERE user_id = $auth`).
- `GET /api/v1/me/donations/:id/receipt` — Stream system receipt PDF for owned donation.
- `PUT /api/v1/me/reminder-preference` — Toggle donation reminder preference.
- `POST /api/v1/auth/logout` — Revoke active session.

---

## 6. Admin Panel Routes (`/api/v1/admin`)

Requires active admin session cookie (`admin_session`) and permission verification.

### 6.1 Admin Auth & Session Management
- `POST /api/v1/admin/auth/login` — Email + Password authentication (triggers TOTP challenge if enabled).
- `POST /api/v1/admin/auth/mfa/verify` — Complete TOTP verification.
- `POST /api/v1/admin/auth/reauthenticate` — Elevate session security before sensitive actions.
- `GET /api/v1/admin/auth/sessions` — List active admin sessions (`security:read`).
- `POST /api/v1/admin/auth/sessions/revoke-all` — Revoke all sessions (`security:write`).

### 6.2 Donors & Financials
- `GET /api/v1/admin/donors` — List donors with status, aggregate total, and masked contact info (`donors:read`).
- `GET /api/v1/admin/donors/:id` — View full donor profile (`donors:read`).
- `GET /api/v1/admin/donations` — Filterable donation transaction table (`donations:read`).
- `GET /api/v1/admin/dashboard` — Gross, Net, Refund, Repeat Donor analytics (`reports:read`).
- `POST /api/v1/admin/reports/export` — Request CSV/PDF report download (`reports:export`). Generates private file asset.

### 6.3 CMS Management
- `GET /api/v1/admin/cms/pages/:slug` — Fetch page sections (`cms:read`).
- `PUT /api/v1/admin/cms/pages/:slug/sections` — Update section content & reorder (`cms:write`).
- `POST /api/v1/admin/cms/pages/:slug/publish` — Publish page draft (`cms:publish`).

### 6.4 Media & Storage APIs
- `POST /api/v1/admin/media/upload` — Upload asset (Multipart form). Requires target `visibility: public | private` (`media:write`).
- `GET /api/v1/admin/private-files/:id` — Download private document asset (`files:private_read`).

### 6.5 Dynamic RBAC Operations
- `GET /api/v1/admin/rbac/roles` — List roles & permissions (`rbac:read`).
- `POST /api/v1/admin/rbac/roles` — Create new role (`rbac:write`).
- `PUT /api/v1/admin/rbac/accounts/:id/roles` — Assign roles to admin (`rbac:assign`).
- `PUT /api/v1/admin/rbac/accounts/:id/permission-overrides` — Apply custom allow/deny override (`rbac:assign`).
